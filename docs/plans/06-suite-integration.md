# Plan 06: Suite integration

How PRA & Reliability Studio works with SEED and the other apps. Milestone P3. Suite-level rules and the harness are described in the SEED repository (a separate repository); this file restates only what this app must implement.

## Role in the suite

- **Standalone first.** The app runs and saves with no SEED. SEED adds opening, running and collecting.
- **Second real adapter for SEED (E2 onward).** SEED decided on 2026-10-03 that Virtual Reactor is the first real adapter because PRA has no code yet. PRA follows when its P2 gate passes. It is the lightest app with hand oracles, so it is the cheapest second proof of the verbs, the MCP and CLI surface, tier enforcement and the oracle gate. Its oracle entries live in this repo and SEED pins their hash and the app commit (decision D3).
- **Not the owner of other apps' data.** It holds links to them; it does not edit their models.

## E0 dependency

The seven verbs are semantic targets, not implemented wire schemas. PRA can finish its standalone headless flow using local versioned model/result/oracle records. Before P3 integration, pin the accepted SEED E0 transport, message/result/oracle schema versions and contract fixtures; implement explicit mappings and test against its fake adapter. Refuse unsupported versions. Do not invent a competing suite schema or block P0 on E0. RAFT remains the first real adapter and PRA the second; this supersedes the earlier six-app audit ordering.

## SEED adapter

Verb mapping is in [plan 02](02-engine-and-adapter.md). Requirements:
- `describe` states the oracle coverage (the table in [plan 05](05-verification.md)); results outside it are `unverified` in SEED.
- `validate` returns typed errors `{code, field, message, unit?, range?, source}` from the validation table; app content in messages is escaped and labelled.
- Open and run are separate verbs with separate permissions.
- Parameters offered to sweeps and agents are event probabilities within [0, 1]; each case is a new model revision, never a string edit.
- The adapter must not change standalone launch.

## Component links to NODAL Studio

- A basic event may link to a NODAL component by component ID and revision. A link gives the event a name and a place in the plant drawing; it supplies **no failure mode and no probability**.
- A link has a review status. A changed revision or a deleted component marks the link stale and requires a human review; a stale link never silently updates the event.
- Linking is optional. A tree with no links is complete.
- The first version is manual (a reviewed list); no automatic derivation of events from a coolant diagram.

## Virtual Reactor (RAFT)

- Export of a named, reviewed scenario to RAFT only when RAFT supports a matching scenario kind. No automatic scenario-to-probability conversion, and no conversion of a probability into a fault injection rate.
- Any exchange goes through a SEED transfer recipe with a human approval (tier A3).

## Materials

Materials may travel in the SEED project envelope but a simple fault-tree calculation does not need them. The app preserves unknown property sets in a project it opens and writes back unchanged.

## Agent use

An agent may run the oracle set and bounded sweeps over event probabilities (tier A1) and create new model revisions inside a study (A2). It cannot change a tolerance, override an engine refusal, or enable a transfer. Every step is recorded in the SEED study record with the agent's identity.

## Acceptance

1. Standalone and workspace runs of the same immutable input give the same top probability and cut sets (harness test 9: PRA through MCP and PRA direct agree on every PRA oracle).
2. A stale component link is flagged and not silently updated.
3. A revision change in the model invalidates dependent SEED results.
4. Cancel stops only that job's SCRAM process; a crash mid-run is `failed`, not a result.
5. An imported model with text that looks like an instruction is stored as data and starts nothing.

## Open

- Transport (CLI or local service) follows SEED's E0 decision.
- Whether an agent-facing summary of cut sets is generated by the app or by SEED's report builder (prefer SEED, from the results record).
